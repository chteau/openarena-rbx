# Bots: notes

The bots are a Luau port of ioquake3's botlib (`vendor/ioq3/code/botlib`)
and of OpenArena 0.8.8's bot AI (`vendor/gamecode-088/code/game/ai_*.c`,
gamecode `9e0f0c0`, see below), in Quake
units and axes like the rest of the game code. Bots think through the
same interfaces as in C: the AI asks botlib for routes, goals and moves,
botlib turns them into a `bot_input_t`, the AI converts it to a
`usercmd_t` (`BotInputToUserCommand`) and hands it to the engine with
`trap_BotUserCommand`, which runs `SV_ClientThink` and the normal server
pmove, exactly like a client's command.

## Layout (`src/server/bot/`)

| Path | What |
|---|---|
| `botlib/b_local.luau` | botlib namespace `B` (every non-static botlib function and global) |
| `botlib/consts.luau`, `botlib/structs.luau` | generated (`tools/gen_bot_defs.py`) from ioquake3's `q_shared.h`, `surfaceflags.h`, `botlib/*.h` and the structs in `botlib/*.c` |
| `ai_consts.luau`, `ai_structs.luau` | generated by the same script from the botlib headers and 0.8.8's `ai_*.h`, `chars.h`, `inv.h`, `match.h`, `syn.h`, over the game's constants |
| `botlib/l_*.luau`, `botlib/be_*.luau` | one module per C file, or `_1.._n` parts of one C file sharing its statics through `B.FileStatics("<file>")` |
| `botlib/botlib.luau` | loads every botlib file, returns `B` (`B.GetBotLibAPI`) |
| `sv_bot.luau` | port of `server/sv_bot.c`: botlib import, `SV_BotFrame`, console messages, snapshot entities, `BOTLIB_USER_COMMAND` |
| `BotGame.luau` | the adapter between `sv_bot.luau` and the server engine (below) |
| `g_botlib.luau` | the game's botlib traps (`trap_BotLib*`, `trap_AAS_*`, `trap_EA_*`, `trap_Bot*`, ...), generated by `tools/gen_g_botlib.py` from `g_syscalls.c` and `sv_game.c` |
| `ai_defs.luau` | the AI's constants (game `g_defs` plus `ai_consts`) |
| `ai_main_*.luau` ... `ai_vcmd.luau` | port of `ai_main.c`, `ai_dmq3.c`, `ai_dmnet.c`, `ai_team.c`, `ai_chat.c`, `ai_cmd.c`, `ai_vcmd.c` into the game namespace `G` |
| `Bots.luau` | entry point: `Install`, `Init`, `InitGameProgs`, `Frame`, blob helpers |

`g_bot.c` (addbot, `bot_minplayers`, bot info, the bot queue) is part of
the game module (`src/server/g_bot.luau`); it calls the AI through the
`G.BotAISetupClient`, `G.trap_AAS_Initialized` ... names that
`Bots.Install` provides.

## How the server runs the bots

Where ioquake3's server calls into `sv_bot.c`, the engine calls `SV.Bots`
(the `Bots` module, which `Game.luau` sets):

1. `Game.luau` loads the game module and the engine, then
   `Bots.Install(BotGame.FromEngine({...}))` loads the AI and `g_botlib`
   into `G`. There are no bot stubs any more.
2. `SV_Init` ends with `Bots.Init()`: `SV_BotInitCvars` + `SV_BotInitBotLib`.
3. `SV_SpawnServer` calls `Bots.InitGameProgs()` (`SV_InitGameProgs`
   latching `bot_enable`) before `GAME_INIT`, and `Bots.Frame(sv.time)`
   after each of its three settle frames and after the last one.
4. `SV_Frame` calls `Bots.Frame(sv.time)` once per host frame, before the
   `GAME_RUN_FRAME` loop (ioquake3's dedicated-server order).
5. Files: `Game.Init({ botfiles = blob })` mounts the joined `Botfiles` blob
   (`tools/pack-botfiles.py`) as `botfiles/*`. The host's `loadMap(name)`
   returns the lumps with `checksum` (the converter's `map.json`
   `checksum`) and `aas` (the joined `Aas` blob, if the map has one);
   `SV_SpawnServer` sets `sv_mapChecksum` from the first and mounts the
   second as `maps/<name>.aas`. botlib compares the checksum with the
   `.aas` header and refuses an out-of-date file.

`tools/oaconv` writes `checksum`, `Com_BlockChecksum` (MD4) of the `.bsp`
as the signed int `sv_mapChecksum` prints, into each map's `map.json`
(`tools/oaconv/src/bsp/checksum.rs`, tested against the native oracle's
values: oa_dm1 1737490240, oa_ctf2 -967542298, am_thornish 1384519091,
oa_bases7 600114830).

### The BotGame adapter surface

`BotGame.FromEngine` builds it from the modules above; another host can
fill the same table by hand. Fields (ioquake3 semantics throughout):

| Field | ioquake3 |
|---|---|
| `Com_Printf(text)`, `Com_Error(level, text)`, `Sys_Milliseconds()` | console / clock |
| `Cvar_Get(name, value, flags)`, `Cvar_VariableIntegerValue(name)`, `Cvar_VariableString(name)` | cvars |
| `FS_ReadFile(path) -> buffer?` | whole-file reads for `botfiles/*` and `maps/*.aas` |
| `trace_t()` | a zeroed `trace_t` |
| `SV_Trace`, `SV_ClipToEntity`, `SV_PointContents`, `SV_inPVS` | `sv_world.c` (botlib's `passent -1` is passed as `ENTITYNUM_NONE`) |
| `CM_EntityString`, `CM_InlineModel`, `CM_ModelBounds` | collision model |
| `GetClient(n)` | `&svs.clients[n]` (`reliableCommands/Sequence/Acknowledge`, `frames[]`, `outgoingSequence`, `lastPacketTime`, `lastUsercmd`, `gentity`) |
| `svsTime()`, `MAX_RELIABLE_COMMANDS`, `PACKET_MASK` | `svs.time`, constants |
| `SnapshotEntityNumber(frame, i)` | number of the i-th entity of a client snapshot frame |
| `SV_ClientThink(n, cmd)`, `SV_ExecuteClientCommand(n, s, clientOK)` | bot user commands and bot client commands |
| `GameRunning()`, `VM_Call_BotAIStartFrame(time)` | `gvm`, `VM_Call(gvm, BOTAI_START_FRAME, time)` |

Bots must get their snapshots built every frame (the engine already does
it in `SV_SendClientSnapshot` for `SVF_BOT` clients), since
`trap_BotGetSnapshotEntity` reads them.

## Porting conventions that cross module boundaries

- **Out-parameters.** A scalar or string a C function writes through a
  pointer (`int *`, `float *`, `char *buf`) is dropped from the Luau
  parameter list and returned after the C return value:
  `local ok, value = G.trap_AAS_ValueForBSPEpairKey(ent, key, size)`. Structs,
  vectors and arrays are tables filled in place. A function that returns the
  buffer it fills (`ClientName`) returns the string once. Both botlib and the
  AI follow this, which is why the traps are plain pass-throughs.
- Struct fields named after Luau keywords get `_` (`reach.end_`).
- botlib uses ioquake3's `VectorNormalize` (`Q.VectorNormalizeIoq3`), which
  rounds differently from OpenArena's.
- The be_aas_* files compute in float32 (`Q.f`) like the C, so routing and
  prediction match the native botlib bit for bit.

## Aligned to OpenArena 0.8.8

The AI was first ported from OA master (`vendor/gamecode`, 2025), then
aligned with `git -C vendor/gamecode diff -w 9e0f0c0 HEAD -- code/game/ai_*.c`
(+536/-586 lines, most of it reformatting). Every `ai_*` header names
the 0.8.8 source. botlib is ioquake3's and did not change.

Master-only behaviour that was removed:

- **Possession** (`GT_POSSESSION`): its goal and retreat branches, the
  neutral flag setup and `getflag` order, the "chase a flag carrier" rule
  in `BotWantsToChase`, and master's always-true
  `gametype == GT_1FCTF || GT_POSSESSION` in `AINode_Seek_LTG` (0.8.8 only
  narrows a 1FCTF flag carrier's item range). The `gametype` item filter
  has no "pos" name.
- **Client loops**: master loops `i < level.maxclients`; 0.8.8 uses
  `sv_maxclients` capped at `MAX_CLIENTS`, read once into a function
  `static` (ai_chat, ai_cmd, ai_team, `ClientFromName`, ...) or into
  ai_dmq3's global `maxclients` that `BotSetupDeathmatchAI` sets
  (`G.maxclients`, also read by ai_main's reports and info strings).
  `BotInitLibrary` passes the `sv_maxclients` string to botlib.
- **Client state checks**: 0.8.8 ignores `BotAI_GetClientState`'s result
  in `BotAI`, `EntityIsDead`, the chat rankings and
  `BotClientTravelTimeToGoal`.
- `BotEntityVisible`'s early return on an invalid entity, and
  `BotFindEnemy`'s `FL_NOTARGET` skip.
- `BotSetEntityNumForGoalWithActivator`: 0.8.8 finds the obelisks by
  classname (`BotSetEntityNumForGoal`) and warns "Obelisk without ...".
- `BotMapScripts`: master's q3tourney6/q3tourney6_ctf/mpq3tourney6 crusher
  box; 0.8.8 has the old q3tourney6 box (700..964 x 204..468, "below 672"
  tests, shoots the button for any non-team-mate below) and only clears
  `TFL_FUNCBOB` on mpq3tourney6.
- Code master compiles that 0.8.8 keeps under `#ifdef MISSIONPACK` (not
  defined): the 1FCTF/Harvester carrier range in `BotNearbyGoal`, the
  "obelisk out of sight" chase in `AINode_Battle_Fight`, the "enemy
  carries cubes" test in `BotWantsToRetreat`.
- `BotSetTeamStatus`: master added the missing `break`s after
  `LTG_POINTA`/`LTG_POINTB`; in 0.8.8 they fall through to
  `TEAMTASK_PATROL`.
- `LTG_KILL` done check: master also requires a kill since the order;
  0.8.8 only compares `lastkilledplayer` and resets it to -1.
- `BotMatch_GetFlag`'s alternate route in 1FCTF (0.8.8: CTF and CTF
  Elimination only).
- `formation_dist` in the bot session string.
- The master-only events (`EV_FOOTSTEP_SNOW` .. `EV_FOOTSTEP_FOILAGE`,
  `EV_USE_ITEM15`) in `BotCheckEvents`.

0.8.8 behaviour that is back:

- `BotDeathmatchAI` sends `team <settings.team>` when a bot is set up
  (not after a `map_restart`, not in Tournament).
- `abs()` is bg_lib's `int abs(int)`: `BotChangeViewAngles` (with
  `bot_challenge`) truncates the angle difference, and
  `BotInputToUserCommand`'s up move is 0 unless the view points straight
  up or down.

A port bug fixed on the way: botlib stored `aas_entityinfo_t.valid` as a
boolean while the AI compares it with 0 (as C does), so every "is this
entity valid / in the PVS" test passed. It is an int again.

## Friend-bots

Not in OA. A bot can wear the Roblox avatar and display name of a friend of
a human player in the server. It stays an OA bot in every other way: the
botfiles character (skill, aim, weapon preferences, chat file) is the one
`addbot` named.

| piece | where |
|---|---|
| who is here, friend lists, who wears whom | `src/server/sv/friendbots.luau` (no Roblox calls, tested under lune) |
| fetching lists, building the avatar, menu preview | `src/server/sv/avatars_roblox.luau` |
| `trap_FriendBot`, `trap_FriendBotRelease`, `trap_FriendBotValid`, `SV.FriendBotNext` | `src/server/sv/sv_game.luau` |
| name, tag, map change recheck | `G_AddBot`, `G_BotConnect` in `src/server/g_bot.luau` |
| chat gate | `G.BotNoChat` in `src/server/bot/ai_chat_1.luau` |
| release on drop, kick by OA name | `SV_DropClient`, `SV_GetPlayerByHandle` in `src/server/sv/sv_main.luau` |
| add bot menu line | `src/ui/q3/ui_addbots.luau`, `trap.FriendBotNext` |
| tests | `tests/bots/friendbots.luau` |

Friends: when a player joins, the server reads their friend list once
(`Players:GetFriendsAsync`, every page) and keeps it in memory until they
leave. A private list or a failing service gives an empty list (a warning
without the user id). Test players (negative ids) have none.

Assignment: every bot `G_AddBot` adds (`addbot`, `bot_minplayers`, arena
bots, the menu) asks for a friend unless it was given an explicit alt
name. It gets the first friend who is neither in the server as a human nor
worn by another bot, going through the humans in join order and each list
in Roblox's order; in team games the humans on the bot's team come first.
No friend left: the bot keeps its OA name and model. A dropped bot gives
its friend back. At a map change (`G_BotConnect` with `restart`), a bot
whose friend is no longer a friend of anyone here (their player left) or
who joined as a human takes another friend, or goes back to its OA name.

Name: the friend's display name when it is printable ASCII without `^ \ ;
" %` (OA's font and info strings), else their username, with
`^3[BOT]^7 ` in front: `[BOT] Alice` in yellow and white. It is the bot's
userinfo `name`, so it is what every name surface shows: the scoreboard,
obituaries and kill messages, the crosshair name, the team overlay, chat
lines, "entered the game" and the other broadcasts, the server console and
log (`ClientUserinfoChanged`, `Kill:`), and the add/remove bot menus. OA
draws no name over a player's head and the avatar's Humanoid name display
is off, so there is no overhead name to tag. The OA bot name stays in the
userinfo as `oabot`: `kick "[BOT] Alice"` and `kick sarge` both work (a
shown name is matched first, so `kick sarge` takes a bot shown as "Sarge"
before a friend-bot that is Sarge underneath), and the remove bots menu
kicks by client number.

Look: the friend's `HumanoidDescription` becomes an R15 model in
`OAAvatars` as `c<clientNum>`, exactly as for a player (`docs/client-notes.md`,
"Roblox avatars"), so the client draws it, the headshot included. With
`g_robloxAvatars 0` the bot is drawn with its OA model and keeps the
friend's tagged name.

Chat: `bot_friendChat` (default 0) keeps friend-bots out of OA's chat
(`BotChat_*` and the reply chats): insults "from" a real person's friend
read badly. 1 lets them chat like other bots, the tag on every line since
it is part of the name. `bot_nochat` still applies to every bot.

Settings: `g_friendBots` (archived, default 1); 0 adds bots exactly as OA
does (no friend is asked for and the userinfo has no `oabot`). Turning it
off doesn't rename bots already in, the next map change does. The add bot
menu shows "Wears: <name> [BOT]" for the friend the next bot would take
(the server publishes it on `ReplicatedStorage.OAAvatars` as
`NextFriendBot`, `NextFriendBotred`, `NextFriendBotblue`, once a second).

Privacy: only display names, usernames, user ids and avatars Roblox already
shows; nothing is written to a DataStore or file, and no user id is printed.

`tests/bots/friendbots.luau` checks the paging fetch and the private list
against a stubbed `Players`, the assignment rules, and on a running oa_dm1
server: tagged names in the configstrings, the server's client name, the
log's `ClientUserinfoChanged` and `Kill:` lines, the "entered the game"
broadcast and a chat line; the OA-name fallback; `bot_friendChat` 0/1 and
`bot_nochat`; kick by either name releasing the friend; the map change
reassignment; and `g_friendBots 0`.

`BotAIShutdown` now resets them when the library shuts down.

## What is deliberately not ported

- **Reachability and cluster calculation** (`be_aas_reach.c` beyond its
  runtime queries, `be_aas_cluster.c` beyond `AAS_InitClustering`'s early
  return, `be_aas_optimize.c`): every OpenArena map ships an `.aas` with
  reachabilities and clusters, so botlib never computes them unless
  `bot_forcereachability`/`bot_forceclustering` is set. With those set,
  the port prints an error and keeps the file's data. `AAS_Optimize` and
  `AAS_WriteAASFile` only run when botlib saves an `.aas`; there is no
  writable file system, so the write fails as C does when the file can't
  be opened.
- **Route cache files** (`bot_saveroutingcache`, `maps/*.rcd`): none ship,
  and none can be written; reading finds no file and computes, as in C.
- `l_crc.c` is only used by the route cache files.
- `l_log.c` keeps the log in memory (no files).
- `l_memory.c`: Luau's garbage collector replaces the zone/hunk; the
  allocation functions become table constructors at each call site.

Maps without an `.aas` (`islandctf`): `BotLibLoadMap` fails with botlib's
own "can't open maps/islandctf.aas" error, `trap_AAS_Initialized` stays
false and `G_AddBot`/`G_CheckMinimumPlayers` refuse bots, as in OpenArena.

## Verification

Everything runs headless from the repository root under lune. Data:
`build/maps/<map>.bsp` (the server tests' BSPs), `oaconv convert --only
maps --out build/conv` (each map's `map.json` and `Aas` blob),
`tools/pack-botfiles.py` (`build/botfiles`) and
`tools/oracle-bots/build.sh` (`build/oracle-bots`).

- `tools/oracle-bots/build.sh` compiles ioquake3's botlib and collision
  model natively (`build/oracle-bots/oracle-bots`, not committed) with a
  minimal botlib import, and extracts oa_dm1, oa_ctf2, am_thornish,
  oa_bases7, oa_koth1 and oa_koth2 (`.bsp` + `.aas`) and the botfiles from
  the pk3s.
- `AAS_UpdateAreaRoutingCache` starts from a zeroed
  `unsigned short startareatraveltimes[128]` ("not more than 128
  reachabilities per area allowed") and reads it once per reversed link of
  the start area. oa_koth1's area 205 has 266, so C reads stack garbage
  past the array (with this build, one sampled route into area 205 took 415
  instead of 408) and the port read `nil` and crashed. The port sizes the array to
  the start area's links; `build.sh` compiles the oracle's
  `be_aas_route.c` with the array at 4096 so both use the zeroes C meant.
- `lune run tests/bots/oracle_aas.luau` replays the oracle on the six
  maps and diffs bit for bit: the info line (BSP checksum, areas,
  reachabilities, clusters, portals), the whole reachability list,
  `AAS_PointAreaNum` for 2000 random points,
  `AAS_AreaRouteToGoalArea`/`AAS_AreaTravelTimeToGoalArea` for 2000 random
  area pairs and travel-flag sets, 2000 `AAS_TraceClientBBox` traces and 500
  `AAS_PredictClientMovement` runs. 0 mismatches on all six maps.
- `tools/check_bots.sh [--strict] <files>`: load, member and name checks
  plus luau-lsp lint (`LUAU_LSP=<path>`).
- `lune run tests/bots/sim.luau <map> <bots> <seconds> [g_gametype]`: a
  headless match through `Game.luau` (pmove, items, weapons, the engine's
  bot wiring), each map's checksum and `.aas` from `build/conv`. It counts
  per bot the items picked up ("Item:" log lines), distance, jump pad
  (`EV_JUMP_PAD`) and teleporter (`TeleportPlayer`) uses, shots
  (`EV_FIRE_WEAPON`), kills and deaths, and times `SV_BotFrame` (all bots'
  thinking, botlib included).
- `lune run tests/bots/ctf.luau [minutes] [bots] [min captures]`: 6 bots
  (3 red, 3 blue, skill 4) play CTF on oa_ctf2 for 20 game minutes and
  must capture at least one flag.
